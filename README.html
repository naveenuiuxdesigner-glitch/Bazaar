1. Run Bazaar on your computer

You need Node.js 20.19+ or 22.12+ and npm. Open a terminal in the Bazaar project folder, then run:

npm install
npm run dev

Open the local address Vite prints in your terminal. It is usually http://localhost:5173.

Other commands:

  • npm run build — prepare a production build in dist/.
  • npm run preview — preview that build locally.
  • npm run lint — run Oxlint code checks.

For static hosting that needs hash routes, set VITE_HASH_ROUTER=true before building. Normal browser routes are the default.

3. What shoppers can do

Discover

Browse the homepage campaigns, categories, deals, featured brands, and recommended products.

Search and filter

Use suggestions, category/type and brand filters, rating, discount, delivery, stock, and price ranges. Sort by relevance, price, discount, rating, or newest.

Inspect products

See specifications, seller, price and MRP, delivery and returns, offers, and recommendations. Fashion and footwear have size selectors.

Save and compare

Wishlist products, revisit recently viewed items, and compare up to four products side by side.

Quick view and cart

Open quick view from product cards, add items to cart, update quantities, save eligible items for later, and apply coupons.

Orders and account

View a simulated tracking timeline, request returns, print invoices, manage account details, and read help FAQs.

Price range: listing pages offer preset and custom price filters. On product pages, “Price range” compares today's offer with the listed MRP. There is no historical price chart.

4. The shopping journey

  1. Find a product. Start at Home, browse a category or brand, search, or open Today’s deals.
  2. Choose options. On the product page, select a required size or colour and review details. Verified gallery images appear when the product has them.
  3. Add to cart. Set quantity, review the cart, and optionally use a coupon or save an item for later.
  4. Checkout. Sign in, select or add an address, choose delivery, and check the total.
  5. Choose payment. Select UPI, card, net banking, EMI, or cash on delivery. The page validates entries and simulates payment.
  6. Follow the order. View confirmation, invoice, order details, and the accelerated demo tracking timeline.

Payment offers, EMI, delivery dates, cancellation, and order progress are all local simulations.

5. Device exchange (demo)

Eligible mobile, laptop, TV, appliance, and electronics product pages offer an optional “Exchange an old device” form. Enter the old device’s brand, model, age, and condition to see an example credit estimate.

The estimate follows the item through cart, checkout, and the demo order. It is not a real valuation: no trade-in partner is contacted, and no inspection or pickup is arranged.

Product records include IDs/SKUs, category and subcategory, brand, seller, price/MRP/discount, ratings, stock, specifications, delivery and return details, tags, options, and image metadata. Much of this is seeded practice data, not a live seller feed.

Where product data lives

  • src/data/products.js builds the main product records and image matching rules.
  • src/data/catalogExpansion.js contains the 503 added records. Keep its category and total-count checks updated when changing it.
  • src/data/productImages.js maps product IDs to photo files and attribution.
  • Place product photos under public/products/. Add only real, matching alternate views or colour photos; don’t duplicate or mirror an image to imply another angle.
  • src/lib/productOptions.js provides standard clothing and shoe sizes. The demo does not track stock per size.

7. Product images: current status

Images are static local files, not live retailer feeds. Product image matching checks source titles against the product model, colour, product identity, and accessory terms. Unmatched assets are withheld from the product page instead of being presented as the wrong item.

700products audited
505valid primary images
195without a usable match
1with multiple mapped views

The 195 without a usable match are 99 products with no image file and 96 whose mapped image did not pass product-title matching. There are no duplicate image hashes among the 505 valid images.

Three-angle coverage is not finished. The gallery can display thumbnails and navigate between genuine image files, but only one product currently has multiple mapped views. Most products do not yet have front, side, back, or detail photos.

Image files and credits are in public/products/ and src/data/productImages.js. Sources include static product listing images from Amazon India and Flipkart, plus credited Wikimedia Commons and other assets. Homepage lifestyle image credits are in src/data/photoCredits.js and shown on the Credits page.

9. Look and feel

Colour

Navy and slate form the base. Blue marks primary actions, violet Bazaar Plus, coral deals, green savings/delivery, and amber ratings.

Type

Plus Jakarta Sans is used for display headings; Inter is used for interface and body text. Prices use tabular numerals.

Shared pieces

Buttons, fields, cards, banners, ratings, price labels, drawers, overlays, toasts, and loading skeletons reuse shared components.

Responsive behavior

Desktop gets full navigation and a filter sidebar; mobile uses compact navigation, filter/sort sheets, and touch-friendly controls.

Framer Motion powers selected carousel, drawer, and interaction transitions. Shared motion components respect reduced-motion preferences.

10. How the app is built

React 19 Vite 8 Tailwind CSS 4 React Router 7 Framer Motion Lucide Oxlint

  • src/App.jsx defines routes and lazy-loaded pages.
  • src/components/ contains shared navigation, homepage, listing, product, cart, checkout, overlay, and UI components.
  • src/context/StoreContext.jsx manages cart, wishlist, compare, location, coupon, browsing history, and saved-for-later state.
  • src/context/AccountContext.jsx manages the demo user, addresses, payment methods, and orders.
  • src/services/ provides local mock catalogue, account, and order behavior.
  • src/data/ stores product data, categories, sellers, banners, payment rules, and image records.

Cart and browsing preferences use browser localStorage keys prefixed with bazaar:. Account records use per-user local storage. Clearing browser site data resets the demo.

11. What is still a demo or incomplete

  • No production API, database, payment gateway, inventory service, or fulfilment integration.
  • Product, price, rating, review, stock, seller, and delivery data are examples.
  • 195 products currently have no usable matched image; only one product has a multi-image gallery.
  • Search, filters, recommendations, checkout, payment, and order tracking run locally as simulations.
  • Exchange estimates are illustrative only. There is no trade-in partner, inspection, or pickup.
